# Quick Chat Spotlight

A standalone Wails v2 binary spawned by the Isoform desktop app. It provides a frameless, always-on-top floating panel — summoned via global hotkey — that lets users chat with the AI agent without switching to the main Isoform window. The UX is modeled after Raycast / Alfred / PowerToys Run.

## Architecture

```
┌─────────────────────────────────────────────────┐
│  Isoform Desktop (wails-gui)                      │
│  ┌───────────────────────────────────────────┐  │
│  │  spotlightSupervisor                      │  │
│  │  - spawns quick-chat-spotlight binary     │  │
│  │  - passes --listen-port, --ipc-token,     │  │
│  │    --yansu-port                           │  │
│  │  - reads SPOTLIGHT_IPC_PORT and           │  │
│  │    SPOTLIGHT_ASSET_PORT from stdout       │  │
│  │  - drives panel via POST /show, /hide,    │  │
│  │    /quit to localhost IPC                 │  │
│  └───────────────────────────────────────────┘  │
│                    │ IPC (localhost HTTP)        │
│  ┌───────────────────────────────────────────┐  │
│  │  quick-chat-spotlight (this binary)       │  │
│  │  ┌─────────────────────────────────────┐  │  │
│  │  │  Go: main.go + IPC server           │  │  │
│  │  │  - Wails v2 runtime                 │  │  │
│  │  │  - window management (frameless,    │  │  │
│  │  │    always-on-top, auto-hide-on-blur) │  │  │
│  │  │  - Win32 helpers (focus, DWM,       │  │  │

│  │  ├─────────────────────────────────────┤  │  │

│  │  │  - PillInput (compact 768x88)       │  │  │

│  │  │  - SSE streaming from host bridge   │  │  │
│  │  │  - reuses main UI chat components   │  │  │
│  │  └─────────────────────────────────────┘  │  │
│  └───────────────────────────────────────────┘  │
```

## Two-View Design

The panel transitions between two modes via a bottom-anchored opacity cross-fade:

**Pill View** (768x88) — The compact entry point shown on every hotkey summon:
- Isoform logo + detection chip (app context + suggestion)
- Single-line textarea with mic and send buttons
- Auto-hides on blur (clicking outside dismisses the panel)
- Esc dismisses the panel

**Conversation View** (768x650) — Expands upward when the user submits a prompt:
- Header with close (x) and "Open in Isoform" buttons
- Full chat surface reusing main UI's `GroupedStreamList`, `ProcessingBlock`, `TypingIndicator`
- Follow-up input with mic/send/cancel buttons
- Auto-hide-on-blur disabled (user can glance at other apps)
- Permission request cards, deliverable proposals

Both layers are always mounted; the inactive one is `opacity: 0; pointer-events: none`. This avoids layout reflow during the transition. The Go side atomically resizes the window via Win32 `SetWindowPos` (or Wails two-step fallback on macOS) while the CSS cross-fade runs.

## Key Components

### Go Backend

| File | Purpose |
|------|---------|
| `main.go` | Wails app entry point, IPC server, host-lifecycle watchdog, window lifecycle, and shared Wails bindings |
| `dwm_rounded_windows.go` | Win32 window subclassing (WndProc for auto-hide-on-blur), DWM dark mode, taskbar hiding via `WS_EX_TOOLWINDOW`, `SetWindowPos` atomic resize |
| `dwm_rounded_other.go` | No-op stubs for macOS/Linux builds |
| `winfocus_windows.go` | Win32 `SetForegroundWindow` + `AttachThreadInput` trick to steal keyboard focus on show; `findWindowByTitle` helper |
| `winfocus_other.go` | No-op stub for non-Windows |
| `winver_windows.go` | `isWindows11OrGreater()` via `RtlGetVersion` |
| `winver_other.go` | Returns `false` on non-Windows |

### IPC Server

The Go binary binds a localhost-only HTTP server on the port passed via `--listen-port`. Routes:

| Endpoint | Auth | Purpose |
|----------|------|---------|
| `GET /health` | No | Liveness probe |
| `POST /show` | Token | Show panel, reset to pill, emit `spotlight:show` event with detection context |
| `POST /hide` | Token | Hide panel, emit `spotlight:hide` event |
| `POST /quit` | Token | Graceful shutdown |

Auth uses constant-time token comparison via `crypto/subtle`. The token is a per-session random value generated by the supervisor.

The helper also probes the Isoform host bridge every 5 seconds. After three consecutive failures it exits, preventing orphaned helper and WebKit processes when the parent is force-stopped or crashes before it can send `/quit`.

### React Frontend

| File | Purpose |
|------|---------|
| `App.tsx` | Root component — owns view state (pill/conversation), theme sync, stage layout with dual-layer cross-fade |
| `PillInput.tsx` | Compact input card with detection chip, voice input, autofocus on summon |
| `ConversationPanel.tsx` | Full chat surface with streaming, follow-ups, permission cards, edit/resubmit |
| `DetectionChip.tsx` | Shows detected app name + icon, clickable to activate a suggestion |
| `chat/reducer.ts` | Pure reducer for streaming state — mirrors main UI's `useAgentStreaming` logic |
| `api/yansu.ts` | API client for Isoform host bridge (`/api/spotlight/*`) — suggestions, submit, SSE stream, theme, voice |
| `api/types.ts` | TypeScript types: `AgentEvent`, `StreamEvent`, `Suggestion`, `DetectionContext` |
| `lib/wails-app-stub.ts` | Redirect target for main UI's `wailsjs/go/main/App` imports — re-exports spotlight bindings + no-op stubs for ~200 methods spotlight doesn't have |
| `index.css` | Imports main UI's full theme, platform-specific body backgrounds, legacy token aliases |

### Build Tooling

| File | Purpose |
|------|---------|

| `wails.json` | Wails v2 project config (`quick-chat-spotlight` binary, pnpm toolchain) |

## Key Design Decisions

### Bottom-Anchored Window

The panel is anchored to `88%` of screen height from the top. When the pill (88px) grows into the conversation (650px), the window expands _upward_ while the bottom edge stays fixed. This keeps the input bar at the same screen position — matching the chat-input dock pattern of ChatGPT / iMessage / Discord.

### Always-Mounted Dual Layer

Both `PillInput` and `ConversationPanel` render simultaneously (inactive layer is `opacity: 0`). This means the conversation panel is already laid out at its intrinsic 650px height before the cross-fade starts, avoiding mid-animation reflow even though the OS window changes size at the same time.

### Component Reuse via Import Stubs

The spotlight reuses main UI chat components (`GroupedStreamList`, `ProcessingBlock`, `StreamCard`, `Composer`, `MarkdownContent`) directly from `../../frontend/src/`. These components import `wailsjs/go/main/App` for Wails bindings. The Vite plugin redirects those imports to `wails-app-stub.ts`, which:

- Re-exports the 6 real spotlight bindings (`GetConfig`, `HideWindow`, `ResizeMode`, `SetAutoHideOnBlur`, `SetDarkMode`, `SetSurfaceColor`)
- Provides no-op stubs for ~200 other methods
- Returns optimistic values for `GetSubscriptionStatus` and `GetVoiceInputStatus` so reused hooks render correctly
- Bridges `TranscribeAudio` and `InitVoiceInput` through the host bridge (spotlight WebView2 doesn't have the sherpa-onnx cgo binding)

### Platform-Specific Window Handling

- **Windows**: Opaque `WebviewIsTransparent: false`. DWM dark-mode border hint. `WS_EX_TOOLWINDOW` to hide from taskbar. Win32 `SetForegroundWindow` + `AttachThreadInput` to steal focus. Atomic `SetWindowPos` for pill→conversation resize.
- **macOS**: Translucent `WindowIsTranslucent: true` + `WebviewIsTransparent: true`. CSS `border-radius` paints through to OS vibrancy. No taskbar suppression needed (child of main app, inherits activation policy).

## Usage

### Development

```bash
# Start the standalone dev server (without the main Isoform binary)
cd wails-gui/quick-chat-spotlight/frontend
pnpm install
pnpm dev
# Opens at http://127.0.0.1:5181

# For full integration (with main Isoform), use the wails-gui start script:
./wails-gui/scripts/start-wails-gui.sh
```

### Production Build

```bash
# Build via the main wails-gui build script (includes spotlight):
./wails-gui/scripts/build-wails.sh

# Or build just the spotlight binary:
cd wails-gui/quick-chat-spotlight
wails build
```

### CLI Flags

Passed by the supervisor at spawn time:

| Flag | Description |
|------|-------------|
| `--listen-port=N` | TCP port for the localhost IPC server |
| `--ipc-token=<token>` | Per-session auth token for IPC requests |
| `--yansu-port=N` | Isoform host bridge port for `/api/spotlight/*` calls |

The supervisor passes `--listen-port=0`: the helper binds its own ports and prints `SPOTLIGHT_IPC_PORT=N` and, on macOS, `SPOTLIGHT_ASSET_PORT=N` (its asset server, whose `http://127.0.0.1:N` is the only webview Origin the host bridge allows) on stdout, and the supervisor reads them from there. The host bridge requires the IPC token on every `/api/spotlight/*` call and a JSON `Content-Type` on every POST, and refuses every call while the supervisor runs no helper (see `wails-gui/host_bridge_guard.go`).

### Standalone Dev Fallback

When running `wails dev` without the supervisor, the frontend falls back to `VITE_YANSU_PORT` env var (set in `.env`) to locate the host bridge. It has no IPC token then, so the host bridge refuses its calls: the UI renders, but suggestions, chat and voice need a helper spawned by Isoform.

## Configuration

- **wails.json**: Project name (`quick-chat-spotlight`), output binary name, frontend toolchain (pnpm)
- **vite.config.ts**: Dev server on port 5181, path aliases (`@/` → main UI, `~spotlight/` → spotlight src), Wails import redirect plugin
- **.gitignore**: Ignores `build/bin/` and `quick-chat-spotlight.exe`

## Testing

Run `cd frontend && pnpm test` for the helper appearance suite in the shared main-frontend Vitest harness (including native and Wails event paths). Run `pnpm build` separately for the helper bundle. The main frontend also provides `pnpm exec playwright test --config playwright.patina.config.ts` for WebKit component checks of separate main/helper contexts with synthetic host replies. These tests do not launch a native app or use a real backend.

Theme and language are read from the host on mount, focus and summon. Spotlight always sets `html[data-texture="off"]` before painting, regardless of the main window's Texture preference. It has no appearance poll or hide listener. Live cross-window appearance synchronization moves to a follow-up PR.

Go helper tests live in `main_test.go`; the main host's authenticated appearance route also has real-store coverage in `host_bridge_spotlight_test.go`. The shared main frontend suite covers the chat streaming components.
