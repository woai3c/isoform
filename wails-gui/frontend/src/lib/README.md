# lib

Shared utility modules for the Wails GUI frontend. This directory is the **environment abstraction and domain-logic layer** — it bridges native Wails and plain-browser mode, provides stream-processing helpers, and exposes reusable UI utilities.

## Architecture

The modules are organized into four layers:

```
┌──────────────────────────────────────────────────────────┐
│               Desktop Integration Layer                  │
│  wails-shim-app  │  wails-shim-runtime  │ browser-bridge │
│  (IPC bindings)  │  (window / events)   │ (HTTP/WS proxy) │
└──────────────────────────────────────────────────────────┘
                          ↓
┌──────────────────────────────────────────────────────────┐
│              Domain Logic (stream-helpers.ts)            │
│  Project/session factories · Serialization · Stream      │
│  grouping · Turn splitting · Model/executor abstraction  │
└──────────────────────────────────────────────────────────┘
                          ↓
┌──────────────────────────────────────────────────────────┐
│                      UI Helpers                          │
│  notify.ts  │  tool-icons.ts  │  platform.ts  │ utils.ts │
└──────────────────────────────────────────────────────────┘
                          ↓
┌──────────────────────────────────────────────────────────┐
│                   Collection Utilities                   │
│                      random-name.ts                      │
└──────────────────────────────────────────────────────────┘
```

**Key design principle:** Unified import paths (`@/lib/wails-shim-*`) hide environment complexity. The same component code runs in native Wails WebView and in a plain browser, with the shim layer routing calls appropriately.

## Files

### `wails-shim-app.ts`

Unified shim for the Wails-generated `wailsjs/go/main/App` bindings. On import, it installs a `Proxy` at `window.go.main.App` when running in browser mode so every call is transparently routed through `callAppMethod`. In native Wails mode the real bindings at `window.go.main.App` are used directly with zero overhead. All named exports from the generated module are re-exported, so consumers can `import ... from '@/lib/wails-shim-app'` without any environment awareness.

### `wails-shim-runtime.ts`

Unified shim for the Wails runtime API (`wailsjs/runtime/runtime`). Every exported function checks `window.runtime?.<Fn>` at call time; if present it delegates to the native Wails runtime, otherwise it falls back to browser-native equivalents:

| Category | Exports | Browser fallback |
|---|---|---|
| Events | `EventsOn`, `EventsOnce`, `EventsOnMultiple`, `EventsOff`, `EventsOffAll`, `EventsEmit` | `browser-bridge` `onEvent` / `offEvent` / `bridgeEmit` |
| Logging | `LogPrint`, `LogTrace`, `LogDebug`, `LogInfo`, `LogWarning`, `LogError`, `LogFatal` | `console.*` methods |
| Window | `WindowReload`, `WindowSetTitle`, `WindowGetSize`, `WindowSetSize`, `WindowMaximise`, etc. | `window.location.reload()`, `document.title`, `window.inner*`, no-ops |
| Screen | `ScreenGetAll` | `window.screen` dimensions |
| App lifecycle | `BrowserOpenURL`, `Environment`, `Quit`, `Hide`, `Show` | `window.open`, static env object, no-ops |
| Clipboard | `ClipboardGetText`, `ClipboardSetText` | `navigator.clipboard` API |
| File drop | `OnFileDrop`, `OnFileDropOff`, `CanResolveFilePaths`, `ResolveFilePaths` | no-ops / `false` |

### `wails-shim-models.ts`

Transparent re-export of `wailsjs/go/models` — the TypeScript types auto-generated by `wails generate module`. Provides a stable import path (`@/lib/wails-shim-models`) so both browser and native mode share the exact same type definitions without duplicating them. The underlying file is produced by any `wails dev` or `wails build` run.

### `browser-bridge.ts`

Detects the runtime environment (Wails WebView vs. regular browser) and provides HTTP/WebSocket bridges so the frontend can run outside the desktop app.

- **`isWailsEnvironment()`** — Returns `true` when `window.__wails__` or a native `window.go` is present, and `false` when the browser bridge proxy installed `window.go`.
- **`callAppMethod(method, ...args)`** — POSTs JSON to `http://localhost:34116/api/call` to invoke a Go App method by name, with the bridge token in the `X-Yansu-Bridge-Token` header. The token is read once from `GET /api/bridge-token` (which needs the `X-Yansu-Bridge-Token-Request` header) and read again after a 401, which means the desktop app restarted the bridge. Throws a descriptive error if the bridge server is unreachable (e.g. the desktop app's browser access toggle is off, or the page's origin is not one the bridge answers).
- **`onEvent(eventName, callback)`** — Subscribes to a named event over a WebSocket connection to `ws://localhost:34116/ws?token=...`. Lazily opens the WebSocket on first call, with exponential-backoff reconnection (up to 5 attempts, max 16 s delay); each reconnect reads the token again. Returns an unsubscribe function.
- **`offEvent(eventName)`** — Removes all listeners for a given event name.
- **`emitEvent(eventName, ...args)`** — Sends a named event to the server via the WebSocket connection.

### `platform.ts`

Platform detection utilities based on `navigator.platform`:

- **`isMac`** / **`isWindows`** / **`isLinux`** — Boolean flags for the current OS.
- **`getPlatformDisplayName()`** — Returns a user-facing OS name (`"macOS"`, `"Windows"`, `"Linux"`, or `"your system"`) from the browser's `navigator.platform`.
- **`platformToDisplayName(platform)`** — Maps a Go `runtime.GOOS`-style string (e.g. `"darwin"`) to a user-facing display name (e.g. `"macOS"`, `"Windows"`, `"Linux"`, or `"this platform"`). Used when the Go backend reports the host platform.

### `utils.ts`

General-purpose helpers used across the UI:

- **`cn(...inputs)`** — Merges Tailwind CSS class names using `clsx` + `tailwind-merge`.
- **`clamp(value, min, max)`** — Clamps a number within `[min, max]`.

### `notify.ts`

Notification helpers that unify in-app toasts and OS desktop notifications.

- **`notifyToast(title, body, type?, toastOpts?, action?)`** — Always shows an in-app [Sonner](https://sonner.emilkowal.ski/) toast. `type` is `'success' | 'error' | 'info'` (default `'info'`). Info toasts auto-dismiss after 5 s; success/error toasts after 8 s. Optional `action` adds a clickable button to the toast.
- **`notifyImportant(title, body, type?, toastOpts?, action?, clickData?)`** — For `'success'` type, calls the Wails `NotifyUser` IPC binding to attempt an OS desktop notification. `clickData` is an optional string passed to the OS notification for click handling. If the backend returns `"toast"` (permission denied or app is focused), falls back to an in-app toast. If a desktop notification is sent and `toastOpts.id` is set, the matching loading toast is dismissed. `'error'` and `'info'` types always use an in-app toast to avoid cluttering the OS notification center.

### `tool-icons.ts`

Maps Claude tool names to Lucide icons, labels, and colors for display in the session stream.

- **`getToolMeta(toolName)`** — Returns `{ icon, label, color, phraseKey, needsToolNameSuffix, humanizedName }` for a given tool name (e.g. `Read`, `Bash`, `Grep`). Falls back to a generic icon for unknown tools; MCP tools (`mcp__server__tool`) get a plug icon. `phraseKey` indexes into the i18n keys `chat.tools.running.<key>` / `chat.tools.done.<key>` to produce a present-tense ("Reading files") or past-tense ("Read files") verb phrase for the group header. `needsToolNameSuffix` is true for the generic/MCP fallback phrases, which interpolate `humanizedName` via `{{name}}` in the translation.
- **`getToolSummary(toolName, toolInput, index)`** — Extracts a short human-readable summary from a tool's input (file name, command description, pattern, query, URL hostname, or patched file names for `apply_patch`). Prefers the `description` field over raw command text for shell tools.
- **`isCommandTool(toolInput)`** — Returns `true` when the tool input contains a `command` or `cmd` field (i.e. Bash, shell, `container.exec`). Used to decide whether to render a command-style code block.
- **`isWriteMarkdownTool(toolName, toolInput)`** — Returns `true` if the tool call is a `Write` operation targeting a `.md` file.

### `summary-content.ts`

Helpers for generating short content previews used in summary cards (e.g. knowledge and memory landing pages).

- **`MAX_RECENT_SUMMARY_ENTRIES`** — Constant (`5`) controlling how many recent entries are shown in summary views.
- **`generateContentPreview(content, options?)`** — Returns a trimmed, single-line preview of a multi-line string. Strips lines matching ignored prefixes (default: `#` headings), frontmatter-style metadata lines (`- **Key**:` patterns), and indented nested bullets (children of frontmatter keys). Limits output to `maxLines` (default: `1`) and `maxLength` (default: `120`) characters.

### `stream-helpers.ts`

Core domain logic and data-transformation utilities for AI sessions, projects, workspaces, and stream items.

| Export | Description |
|---|---|
| `STANDALONE_CHAT_PROJECT_ID` | Sentinel ID (`"__standalone_chat__"`) for the standalone chat project. |
| `STANDALONE_CHAT_WORKSPACE_ID` | Sentinel ID (`"__standalone_workspace__"`) for the standalone chat workspace. |
| `emptyStatus` | Default `AgentStatus` value (`{ running: false, ready: false, port: 0 }`). |
| `logPersistError(err)` | Logs a persistence error to the console with a `[persist]` prefix. |

#### ID & factory helpers

| Export | Description |
|---|---|
| `buildId()` | Generates a unique local ID (`timestamp-random`). |
| `createSession(model, workspaceId, label?)` | Builds a default `Session` object. |
| `createWorkspace(label?, isDefault?)` | Builds a default `Workspace` object. |
| `createStandaloneChatProject(model)` | Creates the pre-configured standalone chat `Project` with fixed sentinel IDs. |
| `registerProject(path, model, overrides?)` | Creates a fully hydrated `Project` (with workspace + session), detects git info and Yansu metadata, assigns a sort order, persists it via Wails IPC, and returns the project. |

#### Model helpers

| Export | Description |
|---|---|
| `FALLBACK_MODELS` | Hardcoded fallback list of Claude model options: `sonnet` (displayed as `"Claude"`). Used when the backend model list is unavailable. |
| `DEFAULT_MODEL` | Default model ID (`"sonnet"`). |
| `getExecutorType(model)` | Returns `"codex"` for GPT/Codex/o3/o4 models (by prefix), `"claude"` otherwise. Strips composite effort suffix before checking. |
| `splitModelEffort(model)` | Splits a composite model ID (e.g. `"gpt-5.2-codex:xhigh"`) into `[base, effort]`. |
| `combineModelEffort(base, effort)` | Combines base model and effort suffix into a composite ID. |
| `CODEX_THINKING_LEVELS` | Ordered list of thinking-level options (`Default`, `Low`, `Medium`, `High`, `Extra High`). |
| `CODEX_SESSION_MODES` | Ordered list of Codex session modes (`Full Auto`, `Auto Edit`, `Suggest`). |

#### Types

| Export | Description |
|---|---|
| `ModelOption` | `{ id, name, executor }` — a single selectable model. |
| `ExecutorGroup` | `{ name, available, models, default }` — a group of models under one executor. |
| `ExecutorType` | `"claude" \| "codex"` discriminant used to drive executor-specific UI/config. |

#### Persistence conversion

| Export | Description |
|---|---|
| `convertFromStorage(data)` | Deserializes `ProjectData[]` (from Wails persistence) into `Project[]` runtime objects. Handles backwards-compatible composite model IDs and pagination state. |
| `toProjectData(p)` | Serializes a `Project` to `ProjectData` for storage. |
| `toWorkspaceData(w)` | Serializes a `Workspace` to `WorkspaceData`. |
| `toSessionData(s)` | Serializes a `Session` to `SessionData` (strips transient streaming state). |
| `toStreamItemData(item)` | Serializes a `StreamItem` to `StreamItemData` (JSON-encodes `toolInput`). |
| `tryParseJSON(str)` | Parses a JSON string, returning the original string on failure. |

#### Stream rendering

| Export | Description |
|---|---|
| `GroupedStreamItem` | Discriminated union: `single`, `tool-group`, or `thinking-group`. |
| `groupStreamItems(items)` | Preserves stream order while wrapping each individual tool call in a single-row `tool-group`. |
| `Turn` | Interface grouping one user message with its processing items and final assistant reply. |
| `splitIntoTurns(grouped, streaming)` | Splits grouped items into conversation turns, keeping interim assistant text and tool work in processing while surfacing only the trailing assistant summary. |

### `line-diff.ts`

LCS-based line-level diff algorithm for comparing two text strings.

- **`DiffOp`** — `'equal' | 'add' | 'remove'` discriminant.
- **`DiffLine`** — `{ op: DiffOp; text: string }` — one line with its operation.
- **`DiffRowPair`** — `{ left?: DiffLine; right?: DiffLine }` — a side-by-side row pair (either side may be `undefined` for blank gutter cells).
- **`lineDiff(oldText, newText)`** — Computes a flat sequence of `DiffLine` operations using O(n×m) LCS. Suitable for small bodies (< 100 lines); equal lines are preserved, removes mark lines only in the old input, adds mark lines only in the new one.
- **`diffStats(diff)`** — Returns `{ added, removed }` counts. Useful for rendering `+3 −1` summary chips.
- **`pairDiff(diff)`** — Pairs the flat `DiffLine` sequence into `DiffRowPair[]` for a classic two-pane (GitHub/VS Code style) side-by-side layout. Equal lines produce a full row; consecutive remove/add runs are zipped so changed lines align horizontally; trailing unmatched lines produce half-empty rows.

### `random-name.ts`

Lightweight adjective-animal name generator (e.g. `"brave-fox"`, `"swift-orca"`).

- **`randomName()`** — Returns a random `"adjective-animal"` string. Used to generate default labels (e.g. workspace names) without external dependencies.

## Usage

Always import from the shim paths rather than directly from `wailsjs/`:

```typescript
// Wails IPC — works in both native and browser mode
import { SaveProjectState, NotifyUser } from '@/lib/wails-shim-app'

// Wails runtime — events, window, clipboard, etc.
import { EventsOn, ClipboardSetText } from '@/lib/wails-shim-runtime'

// Wails-generated Go types
import type { models } from '@/lib/wails-shim-models'

// Domain helpers
import { registerProject, groupStreamItems, splitIntoTurns } from '@/lib/stream-helpers'

// UI utilities
import { cn, clamp } from '@/lib/utils'
import { notifyImportant } from '@/lib/notify'
import { getToolMeta, getToolSummary } from '@/lib/tool-icons'
```

**Typical stream rendering pipeline:**

```typescript
// Raw items from storage/WebSocket
const raw: StreamItem[] = convertFromStorage(persisted)

// Group tool calls and thinking blocks
const grouped: GroupedStreamItem[] = groupStreamItems(raw)

// Split into conversation turns for rendering
const turns: Turn[] = splitIntoTurns(grouped, isStreaming)
```

## Dependencies

- [`clsx`](https://github.com/lukeed/clsx) — Conditional class name builder.
- [`tailwind-merge`](https://github.com/dcastil/tailwind-merge) — Merges conflicting Tailwind classes.
- [`lucide-react`](https://lucide.dev) — Icon library for tool icons.
- [`sonner`](https://sonner.emilkowal.ski/) — Toast notification library.
- `../../wailsjs/go/main/App` — Wails-generated IPC bindings (`SaveProjectState`, `SaveActiveProjectID`, `NextProjectSortOrder`, `GetGitInfo`, `DetectProject`, `NotifyUser`).
- `../../wailsjs/go/models` — Wails-generated Go model types.
- `../../wailsjs/runtime/runtime` — Wails runtime API (events, window management, clipboard, etc.).
- `@/types` — Shared TypeScript types (`Session`, `Project`, `StreamItem`, etc.).
