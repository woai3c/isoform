# Wails GUI Frontend

React 18 + TypeScript frontend for the **Yansu** desktop application — a Wails-based GUI
providing an AI-assisted development environment with multi-project management, streaming agent
responses, integrated terminal, Git workflow support, activity monitoring, and identity management.

## Overview

This directory contains the complete frontend application built with [Wails](https://wails.io/)
(Go + native WebView — **not Electron**). The frontend communicates with a Go backend through
Wails auto-generated bindings.

## Architecture

### State-Driven Navigation

There is no React Router. Navigation is driven entirely by state variables in `App.tsx`:

- `activeProjectId` / `activeWorkspaceId` / `activeSessionId` — what is displayed
- `appMode` — top-level view: `chat` | `automations` | `handoffs`
- Activity, Knowledge, Memory, Timeline, People, and Settings are rendered as Radix Dialog overlays

### Data Hierarchy

```
Project
└── Workspace[]
    ├── Session[]
    │   └── StreamItem[]   # Messages: user | assistant | thinking | tool | error
    └── Terminal tabs      # Per-workspace xterm.js state
```

All state is managed via custom hooks composed in `App.tsx`, with no external state library.

### Wails Bridge

A custom Vite plugin (`wailsBrowserShimPlugin`) intercepts `wailsjs/` imports at build time and
redirects them to shim modules in `src/lib/`. The shims detect at runtime whether native Wails
bindings are available on `window.go`, falling back to an HTTP bridge (`browser-bridge.ts`)
when running in a regular browser. This means a single build works in both environments.

**Critical:** Whenever a new Go method is added on the Wails `App` struct and any frontend file
statically imports it by name, you **must** also add an explicit `export const Foo = appBinding<...>("Foo")`
line in `wails-shim-app.ts`. The trailing `export * from '@wails-generated-app'` does **not**
cover static ESM imports — skipping this produces a hard runtime crash at module load:
`SyntaxError: Importing binding name 'Foo' is not found.`

`quickChat:invoke`, `quickChat:submit`, and `update:status`.

### Streaming Event Pipeline

```
Go backend
    │ EventsOn('agent:event', handler)
    ▼
useAgentStreaming
    │ Converts AgentEvent → StreamItem
    │ Buffers in pendingEventsRef
    │ Flushes every 150ms to avoid React thrashing
    ▼
useProjects.setProjects()   (immutable session.stream update)
    ▼
App.tsx re-render
    ▼
StreamBody → GroupedStreamList → StreamCard
```

## Internationalization (i18n)

The app supports English and Simplified Chinese via [`react-i18next`](https://react.i18next.com/).
Language is detected at runtime from `localStorage` or browser locale, falling back to English.

**Namespaces:** `common`, `app`, `chat`, `settings`, `onboarding`, `calendar`, `activity`,
`knowledge`, `memory`, `people`

```
src/i18n/
├── index.ts              # i18next.init() — imported once from main.tsx
├── i18next.d.ts          # TypeScript augmentation for typed t()
└── locales/
    ├── en/               # English — source of truth for every key
    └── zh-CN/            # Simplified Chinese
```

**Conventions:**
- English is the source of truth. Every key must exist in `locales/en/<ns>.json`.
- Never use inline fallback values (`t('key', 'fallback')`) — missing keys must surface as bugs.
- The TypeScript augmentation type-checks keys against English JSON at compile time.
- See `src/i18n/README.md` for the full convention.

## Quick Start

```bash
# Install dependencies
pnpm install

# Frontend-only dev server (defaults to 5173, auto-picks free port)
pnpm run dev

# Production build
pnpm run build

# Run tests
pnpm run test
```

For the full desktop app, use from the repo root:

```bash
./start-demo.sh                           # Full-stack demo
./wails-gui/scripts/start-wails-gui.sh    # Wails dev mode (Go + WebView)
```

> Never run raw `wails build` or `wails dev` — use the scripts in `wails-gui/scripts/` for
> proper code signing, entitlements, and embedded bundle handling.

## Testing

Vitest + `@testing-library/react` with jsdom:

```bash
pnpm run test            # Run once
pnpm run test:watch      # Watch mode
```

Test files live alongside source under `src/` with `.test.{ts,tsx}` extensions. Configuration
is in `vite.config.ts` under the `test` key (jsdom environment, global test APIs).

```bash
pnpm exec playwright test

```

See `playwright.config.ts` for configuration.

## Theming

Two themes defined in `src/themes/`, applied via CSS custom properties on `data-theme`:

- **Paper** (light, default) — neutral light palette (`#ffffff` background)
- **One Dark** (dark) — near-black dark palette (`#101010` background)

Theme preference is persisted in `localStorage` under `yansu.theme`. The inline script in
`index.html` applies the theme before first paint to prevent flash of unstyled content.
