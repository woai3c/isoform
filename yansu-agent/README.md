# Yansu Agent

Local development companion that syncs your project's knowledge base and context with the Yansu cloud, enabling AI coding assistants to understand your project better.

## Features

- **Filesystem-based Knowledge Sync**: Read/write knowledge through simple markdown files
- **Skills Synchronization**: Automatically sync skills to multiple AI agents (Claude Code, Cursor, Windsurf, etc.)
- **Automatic Knowledge Capture**: AI-powered git hooks extract knowledge from every commit
- **Works with Any AI Agent**: Claude Code, Cursor, Windsurf, Copilot, Goose, and 10+ more
- **Project Context Sync**: PRD, scenarios, and decisions automatically synced
- **Slack Relay**: Daemon mode for routing Slack messages to AI tasks or CLI commands
- **Self-Update**: Built-in `yansu update` to stay on the latest release

## Quick Start

### 1. Authenticate

```bash
yansu login
```

### 2. Clone a Project

```bash
# Format: org/product/project
yansu clone acme/web-app/user-auth-feature
cd user-auth-feature
```

This will:
- Create project directory
- Download project context (requirements, scenarios, decisions)
- Sync the knowledge base
- Sync skills to all supported AI agents
- Set up the `.something/` directory

### 3. Start Coding

Use your favorite AI coding assistant:

```bash
claude  # or codex, gemini, etc.
```

The AI assistant can read:
- `.something/context.md` - Project requirements and decisions
- `.something/knowledge/*.md` - Coding guidelines and patterns

### 4. Stay Updated

Pull the latest changes from your team:

```bash
yansu pull
```

This will:
- Pull the latest code from git
- Download updated knowledge from the cloud
- Sync skills to all supported AI agents
- Sync project context (PRD, scenarios)

## Usage

### Reading Knowledge

AI assistants can directly read files in `.something/knowledge/`:

```markdown
# .something/knowledge/error-handling.md

# UUID
know_xxx

# Trigger
error handling pattern

# Content
All API errors should return unified format...
```

### Creating Knowledge

Write to `.something/new-knowledge/<name>.md`:

```markdown
# Action
create

# Trigger
login rate limiting implementation

# Content
Use Redis INCR + EXPIRE for sliding window rate limiting...
```

Run `yansu push` or the git hook will automatically:
1. Push to the cloud
2. Move to `.something/knowledge/`
3. Update `_index.md`

```markdown
# Action
update

# UUID
know_xxx

# Trigger

# Content
Updated content...
```

### Deleting Knowledge

```markdown
# Action

# UUID
know_xxx
```

### Logging Activities

Write to `.something/activity/<timestamp>.md`:

```markdown
# Activity

- **Summary**: Added rate limiting to login endpoint

## Details
Implemented Redis-based rate limiting...

## Files Changed
- internal/auth/rate_limit.go

```

### Skills Synchronization

Skills are automatically synced from the Yansu cloud to your local project. The `yansu pull` and `yansu sync` commands download skills and extract them to multiple AI agent directories simultaneously, including:

- `.claude/skills/` - Claude Code
- `.cursor/skills/` - Cursor
- `.windsurf/skills/` - Windsurf
- `.opencode/skill/` - OpenCode
- `.codex/skills/` - Codex
- `.agents/skills/` - Amp
- `.kilocode/skills/` - Kilo Code
- `.roo/skills/` - Roo Code
- `.goose/skills/` - Goose
- `.gemini/skills/` - Gemini CLI
- `.agent/skills/` - Antigravity
- `.github/skills/` - GitHub Copilot
- `.factory/skills/` - Droid
- `skills/` - Clawdbot

Skills are stored as compressed tar archives on the cloud and automatically extracted to all supported agent paths during sync. The sync state is tracked in `.something/skills-state.json` to ensure efficient updates.

### Daemon (Slack Relay)

The daemon command starts a background relay that connects to the Yansu backend via WebSocket and routes incoming Slack messages to local CLI commands or AI task execution.

```bash
yansu daemon start              # Start the relay daemon in the background
yansu daemon stop               # Stop the running daemon
yansu daemon restart            # Restart the running daemon
yansu daemon status             # Check daemon process status
yansu daemon logs               # View daemon log output
yansu daemon logs -f            # Follow daemon log output (like tail -f)
yansu daemon register           # Register current project with the daemon
yansu daemon set-executor       # Set the AI executor (claude or codex)
```

**Key daemon behaviors:**
- Maintains a persistent WebSocket connection to the Yansu backend with exponential-backoff auto-reconnect
- Routes incoming messages to CLI commands or AI tasks (Claude Code / Codex)
- Enforces per-user serial command queuing; up to 3 concurrent AI tasks per user
- Logs output to `~/.yansu-agent/logs/daemon.log`
- Tracks registered projects in `~/.yansu-agent/projects.json`

## Configuration

Global configuration is stored at `~/.yansu-agent/config.json`:

```json
{
  "base_url": "https://dashboard.yansu.ai",
  "web_base_url": "https://dashboard.yansu.ai",
  "api_base_url": "https://dashboard.yansu.ai",
  "sync_interval_minutes": 5
}
```

The authentication token is stored separately in `~/.yansu-agent/token` (mode 0600) and is never written to `config.json`.

Daemon configuration (Slack credentials) is stored at `~/.yansu-agent/daemon.json`:

```json
{
  "slack": {
    "bot_token": "xoxb-...",
    "app_token": "xapp-...",
    "authorized_user_id": "U0123ABC"
  },
  "relay": {
    "team_id": "T0xxxxx",
    "slack_user_id": "U0xxxxx"
  },
  "executor": "claude"
}
```

The `relay` section is optional — the daemon auto-discovers Slack identity from the backend API at startup. Legacy flat-format configs are automatically migrated to this nested format.

Override settings with environment variables:

| Variable | Purpose |
|----------|---------|
| `YANSU_URL` | API / Web base URL override |
| `ANTHROPIC_BASE_URL` | Anthropic API base URL override |
| `ANTHROPIC_API_KEY` | Claude API key for the native agent runner |
| `ANTHROPIC_AUTH_TOKEN` | Bearer token for gateway-based Claude access |
| `SLACK_BOT_TOKEN` | Slack bot token for daemon relay |
| `SLACK_APP_TOKEN` | Slack Socket Mode app token for daemon relay |
| `YANSU_DAEMON_EXECUTOR` | Daemon AI executor: `claude` or `codex` |

### Automatic Knowledge Capture

When you commit code, the git hook automatically:
1. Analyzes your commit diff and message
2. Sends to Yansu AI for knowledge extraction
3. Creates knowledge files in `.something/new-knowledge/`
4. Pushes them to the cloud

**Works with any AI coding tool** - Claude Code, Cursor, Windsurf, Copilot, etc.

## Architecture

Yansu Agent is built in Go 1.23+ with a clean, modular architecture:

```
yansu-agent/
├── cmd/yansu/          # CLI entry point (Cobra commands)
├── internal/
│   ├── auth/          # OAuth authentication & token management
│   ├── client/        # HTTP API client for Yansu backend
│   ├── config/        # Configuration management
│   ├── daemon/        # Slack WebSocket relay daemon
│   ├── gitutil/       # Git utilities & auto-gitignore
│   ├── knowledge/     # Knowledge file parsing & indexing
│   ├── sync/          # Bidirectional sync engine (knowledge & context)
│   └── updater/       # Self-update mechanism
├── agent/             # AgentRunner interface & native in-process runner
├── ksync/             # Public sync API (used by external consumers like wails-gui)
├── docs/              # Documentation
└── scripts/           # Installation scripts
```

### Public API Packages

For external consumers (e.g. `wails-gui`) that need to embed yansu functionality without importing internal packages:

| Package | Purpose |
|---------|---------|
| `agent/` | `AgentRunner` interface with a native in-process runner that drives the Anthropic Messages API and an in-process tool registry |
| `ksync/` | `KSyncer` type exposing Push, Pull, SyncAll, SyncContext, GetSyncStatus, EnsureDirectories, and UpdateIndex methods |

#### `agent` package

```go
import "yansu-agent/agent"

runner := agent.NewNativeAgentRunner(agent.NativeRunnerConfig{
    DefaultModel: "opus",
    ModelAliases: map[string]string{
        "sonnet": "claude-sonnet-4-6",
        "opus":   "claude-opus-4-6",
        "haiku":  "claude-haiku-4-5",
    },
})

if err := runner.Init(ctx); err != nil {
    log.Fatal(err)
}

runID, err := runner.ExecuteTask(ctx, &agent.TaskInput{
    Prompt:          "The login endpoint returns 500 when...",
    Model:           "opus",             // resolved through ModelAliases
    WorkDir:         "/path/to/project",
    SessionID:       "",                 // resume an existing session
    PlanMode:        false,              // read-only planning mode
    ThinkingEnabled: false,              // extended thinking
}, func(event *agent.StreamEvent) error {
    fmt.Printf("[%s] %s\n", event.Type, event.Content)
    return nil
})

runner.CancelRun(runID)
runner.Shutdown()
```

**`AgentRunner` interface:**
```go
type AgentRunner interface {
    Init(ctx context.Context) error
    ExecuteTask(ctx context.Context, input *TaskInput, callback StreamCallback) (runID string, err error)
    CancelRun(runID string) error
    RespondToPermission(sessionID, optionID string) error
    CancelPermission(sessionID string)
    Shutdown() error
    IsReady() bool
}
```

#### `ksync` package

```go
import "yansu-agent/ksync"

// Option A: auto-load credentials from ~/.yansu-agent/ + .something/project.json
syncer, err := ksync.NewKSyncerFromProject("/path/to/project")
if err != nil {
    log.Fatal(err)
}

// Option B: provide credentials explicitly
syncer = ksync.NewKSyncer(baseURL, token, org, product, projectName, projectRoot)

result, err := syncer.SyncAll(ctx)       // push + pull
result, err := syncer.Push(ctx)          // local → cloud only
result, err := syncer.Pull(ctx)          // cloud → local only
err         = syncer.SyncContext(ctx)    // project context only
status, err := syncer.GetSyncStatus()   // last sync time & knowledge counts
err         = syncer.EnsureDirectories() // create .something/ subdirs if missing
err         = syncer.UpdateIndex()       // regenerate _index.md
```

### Design Principles

1. **Zero Configuration**: Works out of the box with sensible defaults
2. **AI-Agnostic**: Works with any AI coding assistant
3. **Filesystem-First**: Knowledge as simple markdown files
4. **Automatic**: Git hooks capture knowledge without user intervention
5. **Multi-Agent Support**: Syncs skills to 14+ AI coding assistants simultaneously
6. **Stateless**: Daemon processes are stateless — safe for concurrent execution

### Security

- Auth token stored separately in `~/.yansu-agent/token` (mode `0600`), never written to `config.json`
- All API communication over HTTPS
- Skill archive extraction enforces: path traversal prevention, symlink blocking, 10 MB per-file size limit, permission sanitization (no setuid/setgid/sticky bits)
- Per-user serial queuing in the daemon prevents cross-user task interference

For detailed architecture documentation, see [ARCHITECTURE.md](ARCHITECTURE.md).

Protected Grep exclusions have direct filesystem regressions that run even
without `rg`. The real Grep execution tests explicitly skip when ripgrep is
missing; installing it enables those integration checks too.

The regular guard suite creates a 10,000-entry Library fixture. The larger
300,000-entry regression is opt-in with `YANSU_TEST_LARGE_LIBRARY=1`; its
five-second tool budget excludes fixture creation and removal. Run these
checks from `yansu-agent/` with a disposable HOME:

```bash
(
  guard_home="$(mktemp -d /tmp/yansu-guard.XXXXXX)"
  trap 'rm -rf "$guard_home"' EXIT
  export GOCACHE="$(go env GOCACHE)" GOMODCACHE="$(go env GOMODCACHE)"
  export HOME="$guard_home" YANSU_AGENT_HOME= GOMAXPROCS=2 GOFLAGS=-p=1
  go test -count=1 -run '^TestProtectedGrepExclusionsWithoutRipgrep$' ./agent/tools
  YANSU_TEST_LARGE_LIBRARY=1 go test -count=1 -v -timeout 15m \
    -run '^TestProtectedToolsLargeLibraryBudget$' ./agent/tools
)
```

The `guard-large-library` macOS job in
[Agent Loop Tests](../.github/workflows/agent-loop-tests.yml) installs ripgrep
when needed and runs the large fixture with Seatbelt and a disposable HOME.
The workflow currently requires manual dispatch; automatic triggers remain
disabled.
